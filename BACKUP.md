# Бэкапы и восстановление FinLife/Centricore

Защита данных по схеме **3‑2‑1**: 3 копии, 2 носителя, ≥1 вне сервера.

| Копия | Где | От чего спасает | Формат |
|---|---|---|---|
| 1. Локальный дамп | сервер `/opt/centricore/backups/*.sql` | кривая миграция, порча данных | plaintext |
| 2. Telegram-канал | приватный канал (через бота) | вайп/изъятие сервера | **зашифровано** `.sql.gz.age` |
| 3. Твоя машина | `pull_backups.ps1` тянет к тебе | вайп/изъятие сервера, потеря Telegram | **зашифровано** `.sql.gz.age` |

**Шифрование асимметричное (`age`):** на сервере лежит только **публичный** ключ (им можно лишь зашифровать). Расшифровать может только твой **приватный** ключ, который хранится **у тебя**, не на сервере. Если сервер заберут со всеми доступами — прошлые бэкапы прочитать нельзя.

## Разовая настройка

### 1. Ключи шифрования (на СВОЕЙ машине, не на сервере)

```bash
# установить age: Windows → winget install FiloSottile.age ; mac → brew install age
age-keygen -o backup_identity.txt      # приватный ключ — ХРАНИ У СЕБЯ
grep 'public key' backup_identity.txt  # строка вида: age1....  (публичный)
```

- `backup_identity.txt` (приватный) — положи в надёжное место: менеджер паролей / зашифрованный диск / **распечатай и убери офлайн**. Без него бэкапы не восстановить.
- Публичную строку `age1...` отправь на сервер:

```bash
echo 'age1XXXXXXXX...' > /opt/centricore/backup_recipients.txt   # можно несколько строк = несколько ключей
```

### 2. age на сервере

```bash
apt-get update && apt-get install -y age        # Debian/Ubuntu
```

### 3. Telegram-канал (off-site копия №2)

1. Создай **приватный канал** (только ты).
2. Бот: используй существующий токен или заведи новый у @BotFather. Добавь бота **администратором** канала (право «публиковать»).
3. Узнай `chat_id` канала: опубликуй в канал любое сообщение, затем
   ```bash
   curl "https://api.telegram.org/bot<ТОКЕН>/getUpdates"   # при блокировке — через прокси: --proxy socks5h://...
   ```
   Найди `"chat":{"id":-100XXXXXXXXXX,...}` — это твой `chat_id` (с минусом).
4. Впиши в `/opt/centricore/.env`:
   ```
   BACKUP_TG_BOT_TOKEN=123456:AA...
   BACKUP_TG_CHAT_ID=-100XXXXXXXXXX
   # TELEGRAM_PROXY уже есть — бэкап использует его же
   ```
> Лимит Bot API — ~50 МБ на файл. Дамп финансов гораздо меньше; если когда-нибудь перерастёт — скрипт предупредит в канал, а копии №1 и №3 продолжат работать.

### 4. Расписание на сервере (cron)

```bash
chmod +x /opt/centricore/backup_prod_db.sh
crontab -e
# каждый день в 03:30 по времени сервера:
30 3 * * * /opt/centricore/backup_prod_db.sh >> /opt/centricore/backups/backup.log 2>&1
```

Проверить сразу: `/opt/centricore/backup_prod_db.sh` — в канал должны прийти файл и «✅ Бэкап ок».

### 5. Пул на свою машину (Windows, off-site копия №3)

1. Настрой SSH-ключ к серверу (чтобы `ssh root@45.144.30.5` работал без пароля).
2. Открой `scripts/pull_backups.ps1`, поправь `$Server` при необходимости.
3. Task Scheduler → создать задачу: ежедневно, действие
   ```
   powershell.exe -ExecutionPolicy Bypass -File "C:\путь\scripts\pull_backups.ps1"
   ```
   Файлы лягут в `%USERPROFILE%\FinLifeBackups`.

## Восстановление

### Быстрый откат (сервер жив) — из локального дампа
```bash
ls -lt /opt/centricore/backups/prod_*.sql
/opt/centricore/restore_prod_db.sh /opt/centricore/backups/prod_YYYYmmdd-HHMMSS.sql
```

### Полное восстановление (сервер вайпнут/новый) — из зашифрованной копии
1. Подними новый сервер, разверни проект (`git clone`, `.env`, `docker compose ... up -d`).
2. Возьми любой `.age` (из Telegram-канала или из `FinLifeBackups`) и свой **приватный** ключ.
3. Восстанови (ключ нужен только тут):
   ```bash
   export AGE_IDENTITY=/path/to/backup_identity.txt
   /opt/centricore/restore_prod_db.sh /path/to/prod_YYYYmmdd-HHMMSS.sql.gz.age
   ```
   (скрипт сам расшифрует → распакует → зальёт)

Либо расшифровать вручную на своей машине и залить plaintext:
```bash
age -d -i backup_identity.txt prod_...sql.gz.age | gunzip > prod.sql
```

## Проверка (раз в квартал)

Бэкап без проверенного восстановления — это надежда, а не бэкап. Раз в квартал:
1. Разверни временную БД (локально/тестовый контейнер).
2. Восстанови в неё свежий `.age` своим ключом.
3. Убедись, что данные на месте (число операций, последние транзакции).

Календарное напоминание на это стоит поставить.

## Модель угроз (что закрыто)

- **Кривая миграция / порча** → копия №1 (быстрый откат).
- **Вайп диска / потеря VPS / шифровальщик** → копии №2 и №3 вне сервера.
- **Изъятие сервера со всеми доступами** → бэкапы зашифрованы, приватный ключ не на сервере; доступ к внешним копиям — только у тебя (Telegram-канал, твоя машина). Свежие бэкапы сервер может лишь *создать/зашифровать*, но не прочитать старые и не удалить их из Telegram/с твоей машины.
- **Потеря приватного ключа** → бэкапы не восстановить. Поэтому ключ — в нескольких безопасных местах, включая офлайн.
