# Кэшбеки по картам — дизайн

Дата: 2026-09-29

## Задача

Перед крупной покупкой пользователь вручную заходит в приложения банков и сравнивает,
какой картой выгоднее заплатить. Нужно держать эти проценты в одном месте и иметь
быстрый доступ к ним с главной страницы.

## Сценарии

1. **Начало месяца.** Пользователь открывает страницу кэшбеков, выбирает карту и вносит
   её категории с процентами на текущий месяц.
2. **Перед покупкой.** С дашборда одним тапом открывает шторку и видит все ставки по
   картам; там же видно, где ставка проигрывает другой карте.

## Принятые решения

| Решение | Выбор | Почему |
|---|---|---|
| Категории | Отдельный справочник, наполняется постепенно | Категории переиспользуются между картами — только так ловятся пересечения |
| Карты | Только `wallet_type = REGULAR`, не архивные | Явное требование пользователя |
| Смена месяца | Каждый месяц с нуля | Выбор пользователя; копирования и «постоянных» ставок нет |
| Основная проекция | Группировка по картам | Совпадает с тем, как пользователь вносит данные |
| Пересечения | Подсветкой, без доп. текста | Выбор пользователя |
| Быстрый доступ | Ссылка в блоке «Финансы» на дашборде → `BottomSheet` | Просмотр без перехода со страницы |

## Модель данных

Обычные CRUD-таблицы, НЕ event-sourced (по образцу `WalletFolder`).

### `cashback_categories`
- `id` PK
- `account_id` Integer, index, **без ForeignKey** (таблицы `accounts` нет)
- `title` String(255)
- `created_at` TIMESTAMP(timezone=True)
- Уникальный индекс по `(account_id, lower(title))` — справочник не должен плодить дубли

### `cashback_entries`
- `id` PK
- `account_id` Integer, index, без ForeignKey
- `wallet_id` Integer (ссылается на кошелёк; FK не ставим — `wallet_balances` это read-model)
- `category_id` Integer, FK → `cashback_categories.id` (своя таблица — FK допустим)
- `percent` Numeric(precision=5, scale=2)
- `period_month` Date — всегда 1-е число месяца
- `created_at`, `updated_at` TIMESTAMP(timezone=True)
- Уникальный индекс по `(account_id, wallet_id, category_id, period_month)` — одна ставка
  на карту+категорию+месяц
- Индекс по `(account_id, period_month)` — основной запрос страницы и шторки

## Backend

Новый роутер `app/api/v2/cashback.py`, префикс `/cashback`, зарегистрировать в
`app/api/v2/__init__.py`. Скоуп — `account_id: int = Depends(get_user_id)`.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/cashback?month=YYYY-MM` | месяц, сгруппированный по картам, с флагами подсветки |
| GET | `/cashback/categories` | справочник |
| POST | `/cashback/categories` | создать категорию (идемпотентно по title) |
| PATCH | `/cashback/categories/{id}` | переименовать |
| DELETE | `/cashback/categories/{id}` | удалить (вместе со своими ставками) |
| POST | `/cashback/entries` | добавить ставку |
| PATCH | `/cashback/entries/{id}` | изменить процент/категорию |
| DELETE | `/cashback/entries/{id}` | удалить ставку |

`month` не передан → текущий месяц.

### Правило подсветки (считается на бэкенде)

Считается один раз на сервере, чтобы страница и шторка не разъехались.

Для каждой категории внутри месяца:
- категория встречается **на одной карте** → `is_best = false`, `is_outranked = false`
  (нейтральная строка, ничего не подсвечиваем);
- категория встречается **на 2+ картах** → у строк с максимальным процентом
  `is_best = true`; у остальных `is_outranked = true`;
- при равенстве максимума `is_best = true` у всех строк с этим процентом.

### Форма ответа `GET /cashback`

```
{
  "month": "2026-09",
  "cards": [
    {
      "wallet_id": 12,
      "title": "Альфа-Банк",
      "entries": [
        { "id": 5, "category_id": 3, "category_title": "Супермаркеты",
          "percent": "5.00", "is_best": true, "is_outranked": false }
      ]
    }
  ]
}
```

Карты без ставок в этом месяце тоже возвращаются (с пустым `entries`) — чтобы на странице
было куда добавлять. **Страница** показывает такие карты, **шторка** их скрывает:
в быстром просмотре пустые карты — лишний шум.

## Frontend

- **Страница** `frontend/app/(app)/cashback/page.tsx`
  - `PageHeader` (title «Кэшбек») + `PeriodSwitcher` по месяцам
  - список по картам; у каждой карты — её ставки и кнопка добавления
  - категория вводится автокомплитом по справочнику; отсутствующая создаётся на лету
  - правка процента инлайн, удаление строки
  - пустое состояние через `EmptyState` (`action={{ label, onClick }}`)
- **Шторка** — `BottomSheet` из `@/components/ui/BottomSheet`
  (props `open/onClose/title/footer/children/detent`), только чтение, текущий месяц
- **Триггер** — ссылка в `frontend/components/dashboard/FinanceBlock.tsx`, открывает шторку
- **Хук** `frontend/hooks/useCashback.ts` — react-query; после мутаций `invalidateQueries`
- **Типы** — `frontend/types/api.ts` (ручные интерфейсы)
- **Навигация** — пункт «Кэшбек» в `NAV_ITEMS` (`AppSidebar.tsx`), иконка `BadgePercent`
- Эмодзи категорий — существующий `frontend/lib/categoryEmoji.ts`, новое поле не вводим
- Цвета только через CSS-переменные (`--app-accent`, `--t-muted`, `--t-faint`)

## Вне объёма (YAGNI)

- Лимиты и кэпы кэшбека («5% до 3000 ₽») — пользователь просил только проценты
- Копирование месяца и «постоянные» ставки — выбран вариант «с нуля»
- Привязка к категориям расходов и подсчёт фактически полученного кэшбека
- Кредитные и накопительные карты
- Проекция «по категориям» — выбрана группировка по картам
